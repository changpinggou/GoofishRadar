一、结论摘要（TL;DR）

  1. 大词有流量但自家零曝光：雷达实测「iPhone」搜索前 90 条结果中屏幕配件占 43 条（赛道流量充足），但自家抽样 3 个商品出现 0 次，全库 906 条快照中「SI未来数科」商品数 = 0；
  2. 三大可修问题：① 标题用「+」连接（苹果14+Pro+Max）破坏搜索分词、编号占位浪费标题字数；② 首图实拍但杂乱（编号纸入镜、暗背景、部分屏朝下）；③ 粉丝仅 3 个、无关注互动，信用与热度信号薄弱；
  3. 最大的免费杠杆是每日擦亮：全部 13 个在售商品逐日擦亮（错峰晚 8 点），配合新品 24 小时流量池（实测自家商品全部显示"24小时内发布"，说明已在吃新品流量，需要用擦亮延续）；
  4. 用 GoofishRadar 做曝光的测量仪表：把买家的真实搜索词加进雷达关键词，每日快照自动记录自家商品是否出现、排名第几、想要数日增多少——每次优化动作都用数据验证。

四、优化方案（三层，按优先级）

L1 个人站设置层（今天即可完成，零成本）

  1. 地区改为深圳：编辑资料 → 地区从"广东省"细化到"深圳"（同城流量 + 与"同城包安装"卖点呼应）；
  2. 简介微调（已较好，只补搜索词根）：在现有文案中自然嵌入「原装屏 / 屏幕总成 / 拆机屏 / 苹果换屏」等买家实际搜索词（保持现有信任表达不变）；
  3. 关注与互粉：0 关注显得不活跃；关注 20~30 个同行/本地数码号，把粉丝从 3 起步拉起来；每个成交买家引导关注（详见 L3）；
  4. 补芝麻信用授权：实人认证已有，芝麻信用分展示是屏幕类目（高客单）最有效的信任信号之一；
  5. 头像专业化：当前个人照可换为门店/工位实拍或品牌 Logo（与"实体店主"定位一致）。

L2 商品层（核心动作，本周内完成）

1. 标题重构公式（去掉编号、去加号、堆真实搜索词）：

【公式】品牌词 + 型号全称 + 词根（原装屏/拆机屏/屏幕总成） + 成色/卖点 + 适用场景
【示例】苹果15ProMax原装拆机屏幕总成 纯原无修 显示完美 维修换屏可用包安装
  • 编号移入描述（库存管理不丢）；
  • 同型号多件用描述区分成色差异（亮度/色差/编号），标题差异化卖点（如"原彩保留""无压排"）；
  • 描述里堆满型号的常见写法变体：15PM / 15 Pro Max / 15promax（买家搜索习惯不一）。

2. 首图重拍标准：亮背景、屏幕点亮显示纯色画面（证明显示正常）、正面朝上、无编号纸杂物；第二张放编号细节图（满足库存管理需求）；

3. 每日擦亮全部在售商品（13 个）：错峰在 20:00–22:00 逐个擦亮（晚高峰流量 + 随机间隔防规律化）；擦亮是单量级最小的持续曝光杠杆；

4. 发布时段：新品/改价安排在 19:00–22:00 发布（吃夜间活跃流量 + 新品 24 小时池）；

5. 服务标签属性化：包邮用属性开关而非标题文字（省出 2 字标题位）；继续用红包（已有）；

6. 补视频：每件商品一条 10 秒点亮视频（显示均匀度/触摸正常），完善度权重 + 转化率双赢。

L3 运营与放大层（1–2 周启动）

  1. 粉丝运营：发货包裹放小卡片"关注领屏幕保养清单/旧屏回收"；成交后主动引导关注+好评（已售 4 单的买家逐个回访）；
  2. 想要转化：对"想要"未拍的用户主动一键出价/优惠（想要数既是排名权重又是成交线索）；
  3. 同城打透：深圳华强北 + 同城包安装是差异化壁垒——描述与首图突出"深圳同城当面装"；同城搜索流量竞争远小于全国词；
  4. 鱼小铺（若符合开通条件）：获得店铺货架/分类/装修能力，宝贝 17 件已有分栏经营的基础；
  5. 付费推广（谨慎）：平台官方推广工具可小额测试，但不做任何站外刷单/虚假交易（合规红线）。

L4 数据驱动迭代（GoofishRadar 作为测量仪表）

原则：每个优化动作前后都要有数据对比，不做无测量的改动。

1. 排名追踪：把买家的真实搜索词加入 config/keywords.yaml（每日快照自动记录）：

tasks:
  - keyword: "苹果15promax原装屏"    # 精准长尾（自家主力型号）
  - keyword: "原装拆机屏"
  - keyword: "苹果屏幕总成"
  - keyword: "iphone换屏"
  - keyword: "苹果14promax屏幕"

每日快照后执行检查（自家 item_id 是否在榜 + 名次）：

.venv/bin/goofishradar item-history <自家商品ID>
# 或按日核对：自家 item_id 是否出现在 data/parsed/{date}/ 对应关键词 JSONL 中

2. A/B 实验：改标题/换首图前后，用 item-history 对比该商品想要数日增量（Δ1d），7 天为一组；

3. 竞品校准：同关键词下 Top 想要数商品的标题/首图/价格即"及格线"，每周对照一次；

4. 告警已就绪：low_volume（日采集 <100）与 high_parse_failure 告警保证追踪本身可靠。

五、边界与风险

  1. 不刷单、不虚假交易——与 T11 合规红线同一边界（平台对虚假交易的处罚远大于慢启动的损失）；
  2. 采集与追踪同样遵守 GoofishRadar 的全局限速与单日预算（新增追踪关键词会占用每日页数预算，建议新增 ≤6 词，预算内腾挪或适度上调 max_pages_per_day）；
  3. 本方案的效果判断以雷达快照数据为准（想要数日增量、在榜名次），不做无法验证的承诺；平台规则可能变化，动作前以闲鱼官方规则页为准。
