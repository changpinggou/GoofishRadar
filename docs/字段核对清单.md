## 二、数据获取路径结论（T01 任务 5）

1. **页面为 ICE 框架 SPA**：HTML 仅是壳（约 13KB），商品数据**不在** HTML 或 `window.__INITIAL_STATE__` 中；
2. **数据经 mtop JSON 接口异步加载**，已实测捕获：
   - 搜索主数据：`mtop.taobao.idlemtopsearch.pc.search`（约 306KB / 30 条）
   - 辅助接口：`...pc.search.shade`、`...pc.item.search.activate`、`mtop.gaia.nodejs.gaia.idle.data.gw.v2.index.get`
   - 详情页接口含 `browseCnt`、`itemStatus`、`hasSoldNumInteger`（已售数量）等
3. **采集策略**：Playwright 页面注册 `response` 监听**被动记录**浏览器自身收到的 JSON（合规，无签名逆向），DOM 选择器仅兜底（锚点选择器 `a[href*="item?id="]` 实测可用）；
4. 原始响应按页落盘存档（`data/raw/YYYY-MM-DD/`），解析可回放。

## 三、翻页机制结论

- 搜索结果页为**页码分页控件**（类名 `search-pagination-*`：页码 1–50 + 左右箭头），**不是**无限滚动；
- 实测点击页码「2」加载成功（29 → 30 张卡片），单页点击+水合约 **7 秒**；
- 注意：翻页按钮为图标无「下一页」文字，定位需用 class 前缀或 JS click（SPA 重渲染会 detach 元素）。

## 四、关键风险实测（影响 T04/T11 设计）

1. **headless 被风控拦截**：详情页 headless 访问返回「非法访问——为了保障您的体验，请使用正常浏览器访问闲鱼~」（有截图）；搜索页 headless 返回 0 条。**结论：采集必须 headed（有头）模式，且不做任何环境伪装**（与 PRD FR-3/FR-10 一致）；
2. 会话 Cookie 持久化（user_data_dir）跨进程复用已验证有效（headless 下首页会话检查亦正常）；
3. 价格字段为字符串（`"833"`），入库需转 float；想要数藏在标签文案中需正则解析；
4. 搜索页单次约 30 条/页，翻页上限 50 页（与 PRD 硬顶一致）。

## 五、加载耗时实测（T11 限速参数依据）

| 页面 | 耗时（domcontentloaded + 水合等待） |
| --- | --- |
| 首页（首次 headed） | 7.7s |
| 首页（重启 headless 会话检查） | 5.4s / 2.6s（headless 无历史） |
| 搜索页第 1 页（headed） | 8.6s |
| 搜索页翻页（点击页码2 + 水合） | 7.0s |
| 商品详情页（headed） | 6.1–6.2s |

**结论**：单页稳定耗时 6–9 秒，PRD 默认页间随机延时 5–15 秒合理偏紧，建议 T04/T11 实施时取 **8–20 秒**（单页 3 页 × 20 关键词 ≈ 15–25 分钟，含详情采集仍在 60 分钟预算内）。详情页间延时不低于 5 秒。
